# S3 API - документация

REST API для работы с объектным хранилищем MinIO/S3, реализованное поверх `S3Client` и подключаемое как Flask Blueprint (`S3Blueprint`).

Базовый префикс всех путей ниже: `/api/s3` (задаётся при инициализации: `S3Blueprint(s3_client, url_prefix="/api/s3")`).

**bruno_s3_API.yml** - коллекция для импорта в Bruno. 

## Формат ответов

- Успешные ответы - JSON (кроме скачивания файлов, где тело - бинарные данные).
- Ошибки - JSON вида:

```json
{
  "error": "Bad Request",
  "message": "Поле 'dst_key' обязательно"
}
```

## Коды ошибок

| Код | Когда возникает |
|---|---|
| `400 Bad Request` | Не передано обязательное поле в теле запроса |
| `404 Not Found` | Объект/бакет/версия не найден (`NoSuchKey`, `NoSuchBucket`, `NoSuchVersion`) |
| `502 Bad Gateway` | Прочие ошибки MinIO (`S3Error`) |
| `500 Internal Server Error` | Непредвиденная ошибка сервера |

## Бакет

### `POST /bucket`
Создаёт бакет, если он ещё не существует.

**Ответ `200 OK`:**
```json
{ "bucket": "test", "status": "ready" }
```

### `GET /bucket/exists`
Проверяет существование бакета.

**Ответ `200 OK`:**
```json
{ "bucket": "test", "exists": true }
```

## Версионирование

Версионирование это свойство бакета. Включение/выключение влияет на все последующие операции с объектами.

При включённом версионировании:
- Каждая запись создаёт новую версию (не затирает предыдущую).
- `DELETE` создаёт delete marker вместо физического удаления.
- Для физического удаления конкретной версии используйте `DELETE /objects/<key>/versions/<version_id>`.

### `GET /bucket/versioning`
Возвращает текущий статус версионирования бакета.

**Ответ `200 OK`:**
```json
{ "bucket": "test", "status": "Enabled" }
```

Возможные значения `status`:

| Значение | Описание                                                   |
|---|------------------------------------------------------------|
| `"Enabled"` | Версионирование активно, новые записи создают новые версии |
| `"Suspended"` | Приостановлено, новые записи создают delete markers        |
| `"Off"` | Версионирование никогда не было включено                   |

### `PUT /bucket/versioning`
Включает или приостанавливает версионирование.

S3 не позволяет полностью отключить версионирование - только **suspend**.
После suspend новые записи поверх существующих не создают версии, а создают delete markers.


**Тело запроса (JSON):**
```json
{ "enabled": true }
```

| Поле | Тип | Описание |
|---|---|---|
| `enabled` | `bool` | `true` - включить, `false` - приостановить |

**Ответ `200 OK`:**
```json
{ "bucket": "test", "status": "Enabled" }
```

## Загрузка объектов

### `POST /objects/<key>/upload-path`
Загружает файл, уже лежащий на сервере, по локальному пути.

**Тело запроса (JSON):**
```json
{
  "source_path": "/tmp/report.pdf",
  "content_type": "application/pdf",
  "presigned": false
}
```
- `source_path` - обязателен.
- `content_type` - опционально, иначе определяется автоматически по расширению.
- `presigned` - если `true`, в ответе также будет presigned GET URL.

**Ответ `201 Created`:**
```json
{
  "key": "reports/report.pdf",
  "bucket": "test",
  "etag": "d41d8cd98f00b204e9800998ecf8427e",
  "url": null,
  "version_id": "Kq7pN8x9..."
}
```
Поле `version_id` присутствует, если версионирование включено. Иначе - `null`.

### `PUT /objects/<key>`
Загружает содержимое тела запроса как есть (raw upload). Полезно для загрузки из скриптов/curl.

**Заголовки:** `Content-Type` (используется как `content_type` объекта).
**Query-параметры:** `presigned=true|false`.
**Тело запроса:** сырые байты файла.

**Пример:**
```bash
curl -X PUT "http://localhost:5000/api/s3/objects/notes/todo.txt" \
  -H "Content-Type: text/plain" \
  --data-binary @todo.txt
```

**Ответ `201 Created`:** аналогичен `upload-path`.

### `POST /objects/<key>/upload-form`
Загружает файл через `multipart/form-data` (например, из HTML-формы или файлового инпута на фронтенде).

**Форма:** поле `file` - обязательно.
**Query-параметры:** `presigned=true|false`.

**Пример:**
```bash
curl -X POST "http://localhost:5000/api/s3/objects/images/photo.png/upload-form" \
  -F "file=@photo.png"
```

**Ответ `201 Created`:** аналогичен `upload-path`.

## Скачивание объектов

### `GET /objects/<key>/download`
Скачивает файл из S3 и отдаёт его клиенту как вложение (`Content-Disposition: attachment`), с определением `Content-Type` по метаданным объекта.

**Ответ:** бинарное тело файла, `404` если объект не найден.

### `POST /objects/<key>/download-to`
Скачивает объект в файл на файловой системе сервера.

**Тело запроса (JSON):**
```json
{ "destination": "/tmp/downloads/report.pdf" }
```

**Ответ `200 OK`:**
```json
{ "key": "reports/report.pdf", "saved_to": "/tmp/downloads/report.pdf" }
```

### `GET /objects/<key>/stream`
Отдаёт объект потоково - подходит для больших файлов, чтобы не загружать их целиком в память.

**Query-параметры:** `chunk_size` (байт, по умолчанию `8192`).

**Ответ:** потоковое бинарное тело с заголовками `Content-Disposition: attachment` и `Content-Length`.

## Метаданные и листинг

### `GET /objects/<key>/info`
Возвращает метаданные объекта (последняя версия).

**Ответ `200 OK`:**
```json
{
  "key": "reports/report.pdf",
  "size": 102400,
  "last_modified": "2026-07-01 12:00:00+00:00",
  "etag": "d41d8cd98f00b204e9800998ecf8427e",
  "content_type": "application/pdf",
  "version_id": null
}
```

### `GET /objects/<key>/exists`
Проверяет, существует ли объект.

**Ответ `200 OK`:**
```json
{ "key": "reports/report.pdf", "exists": true }
```

### `GET /objects`
Список объектов, опционально по префиксу.

**Query-параметры:**
- `prefix` - фильтр по префиксу ключа (по умолчанию пусто).
- `recursive` - `true|false` (по умолчанию `true`).

**Пример:** `GET /objects?prefix=reports/&recursive=true`

**Ответ `200 OK`:**
```json
[
  {
    "key": "reports/2023.pdf",
    "size": 51200,
    "last_modified": "2026-01-10 09:00:00+00:00",
    "etag": "abc123",
    "content_type": null,
    "version_id": null
  }
]
```

## Удаление

### `DELETE /objects/<key>`
Удаляет один объект.

При включённом версионировании создаёт **delete marker**, а не физически удаляет данные.
Для физического удаления используйте `DELETE /objects/<key>/versions/<version_id>`.

**Ответ `200 OK`:**
```json
{ "key": "reports/report.pdf", "deleted": true }
```

### `DELETE /objects`
Удаляет несколько объектов за один запрос.

**Тело запроса (JSON):**
```json
{ "keys": ["a.txt", "b.txt", "c.txt"] }
```

**Ответ `200 OK`:**
```json
{
  "requested": ["a.txt", "b.txt", "c.txt"],
  "failed": ["c.txt"],
  "deleted": ["a.txt", "b.txt"]
}
```

## Presigned URLs

### `GET /objects/<key>/presigned-url`
Генерирует временную ссылку для скачивания (GET) напрямую из MinIO, минуя backend.

**Query-параметры:** `expiry` (секунды, опционально - иначе берётся значение по умолчанию из `S3Config.presigned_url_expiry`).

**Ответ `200 OK`:**
```json
{ "key": "reports/report.pdf", "url": "http://127.0.0.1:9000/test/reports/report.pdf?X-Amz-..." }
```

### `GET /objects/<key>/presigned-put-url`
Генерирует временную ссылку для загрузки (PUT) напрямую в MinIO с клиента, минуя backend.

**Query-параметры:** `expiry` (секунды, опционально).

**Ответ `200 OK`:**
```json
{ "key": "uploads/new-file.zip", "url": "http://127.0.0.1:9000/test/uploads/new-file.zip?X-Amz-..." }
```

## Копирование

### `POST /objects/<key>/copy`
Копирует объект внутри бакета или в другой бакет. Метаданные сохраняются.

**Тело запроса (JSON):**
```json
{ "dst_key": "archive/report.pdf", "dst_bucket": null }
```
- `dst_key` - обязателен.
- `dst_bucket` - опционально, по умолчанию тот же бакет.

**Ответ `200 OK`:**
```json
{
  "src_key": "reports/report.pdf",
  "dst_key": "archive/report.pdf",
  "dst_bucket": "test"
}
```

## Версии объектов

Раздел работает только при включённом версионировании бакета.
Все `version_id` в путях - это строки, возвращённые MinIO (формат похож на uuid в PostgreSQL).

### `GET /objects/versions`
Список **всех** версий объектов в бакете.

**Query-параметры:**

| Параметр | Тип | По умолчанию | Описание |
|---|---|---|---|
| `prefix` | `string` | `""` | Фильтр по префиксу ключа |
| `include_delete_markers` | `bool` | `false` | Включать delete markers в результат |

**Пример:** `GET /objects/versions?prefix=reports/&include_delete_markers=true`

**Ответ `200 OK`:**
```json
[
  {
    "key": "reports/2023.pdf",
    "version_id": "Kq7pN8x9...",
    "is_latest": true,
    "size": 102400,
    "last_modified": "2026-07-01 12:00:00+00:00",
    "etag": "abc123",
    "content_type": "application/pdf",
    "is_delete_marker": false
  },
  {
    "key": "reports/2023.pdf",
    "version_id": "aB3cD4e5...",
    "is_latest": false,
    "size": 98000,
    "last_modified": "2026-06-15 08:00:00+00:00",
    "etag": "def456",
    "content_type": "application/pdf",
    "is_delete_marker": false
  },
  {
    "key": "reports/old.txt",
    "version_id": "Zz9Yx8W7...",
    "is_latest": true,
    "size": 0,
    "last_modified": "2026-07-02 10:00:00+00:00",
    "etag": "",
    "content_type": null,
    "is_delete_marker": true
  }
]
```

### `GET /objects/<key>/versions`
Список версий конкретного объекта. Использовать, когда нужно получить историю одного файла.

**Ответ `200 OK`:** аналогичен `GET /objects/versions`, но только для указанного ключа.

```json
[
  {
    "key": "reports/2023.pdf",
    "version_id": "Kq7pN8x9...",
    "is_latest": true,
    "size": 102400,
    "last_modified": "2026-07-01 12:00:00+00:00",
    "etag": "abc123",
    "content_type": "application/pdf",
    "is_delete_marker": false
  },
  {
    "key": "reports/2023.pdf",
    "version_id": "aB3cD4e5...",
    "is_latest": false,
    "size": 98000,
    "last_modified": "2026-06-15 08:00:00+00:00",
    "etag": "def456",
    "content_type": "application/pdf",
    "is_delete_marker": false
  }
]
```

### `GET /objects/<key>/versions/<version_id>/info`
Метаданные конкретной версии.

**Ответ `200 OK`:**
```json
{
  "key": "reports/2023.pdf",
  "size": 98000,
  "last_modified": "2026-06-15 08:00:00+00:00",
  "etag": "def456",
  "content_type": "application/pdf",
  "version_id": "aB3cD4e5..."
}
```

**Ошибки:** `404` - версия не найдена.

### `GET /objects/<key>/versions/<version_id>/exists`
Проверяет существование конкретной версии.

**Ответ `200 OK`:**
```json
{ "key": "reports/2023.pdf", "version_id": "aB3cD4e5...", "exists": true }
```

### `GET /objects/<key>/versions/<version_id>/download`
Скачивает конкретную версию файла как вложение.

**Ответ:** бинарное тело файла.
**Ошибки:** `404` - версия не найдена.

### `DELETE /objects/<key>/versions/<version_id>`
Физически удаляет конкретную версию.

Необратимо. Данные будут потеряны.
При статусе `Suspended` удаление создаёт delete marker вместо физического удаления.

**Ответ `200 OK`:**
```json
{ "key": "reports/2023.pdf", "version_id": "aB3cD4e5...", "deleted": true }
```

**Ошибки:** `404` - версия не найдена.

### `POST /objects/<key>/versions/<version_id>/restore`
Восстанавливает указанную версию как последнюю.

Реализация: создаёт **новую** версию (copy из указанной). Предыдущая последняя версия не затирается - остаётся в истории.

**Ответ `200 OK`:**
```json
{
  "key": "reports/2023.pdf",
  "restored_version_id": "aB3cD4e5...",
  "new_version_id": "XyZ123...",
  "etag": "def456"
}
```

**Ошибки:** `404` - версия не найдена.

### `GET /objects/<key>/versions/<version_id>/presigned-url`
Генерирует временную presigned GET ссылку для конкретной версии.

**Query-параметры:** `expiry` (секунды, опционально).

**Ответ `200 OK`:**
```json
{
  "key": "reports/2023.pdf",
  "version_id": "aB3cD4e5...",
  "url": "http://127.0.0.1:9000/test/reports/2023.pdf?versionId=aB3cD4e5...&X-Amz-..."
}
```

**Ошибки:** `404` - версия не найдена.
